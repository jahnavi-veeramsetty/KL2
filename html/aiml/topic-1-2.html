Why Python Environment Setup Matters

The Version Conflict Disaster – What Happens Without venv

The Scenario

PROJECT A (Web Scraper) needs: requests==2.28.0
PROJECT B (API Client) needs: requests==2.31.0 (incompatible API!)

Without Virtual Environments

You install requests for Project B: pip install requests==2.31.0
Now Project A BREAKS because requests==2.28.0 is gone!

bash 
pip install django==3.2   # -> installs globally
pip install django==4.2   # -> overwrites! Django 3.2 project breaks!

RESULT: One working project, one broken project. No way to run both. "It works on my machine" → because YOUR machine has the wrong version.

With Virtual Environments

project_a/venv/ → has requests==2.28.0 in isolation
project_b/venv/ → has requests==2.31.0 in isolation

Both projects work simultaneously, forever.

Global vs. Isolated – Side-by-Side Comparison

Without venv (Global Installation)

bash 
pip install requests  # installs to system Python

Problems:

ALL projects share same requests version
Updating for Project B breaks Project A
Deploying to server: no idea which exact versions
Collaborator runs your code: gets different versions
After 6 months: cannot tell which packages belong to which project
sudo/admin required on many systems
bash 
python --version    # 3.11.5
pip list            # 47 packages from ALL projects mixed together

With venv (Isolated Installation)

bash 
python -m venv myproject_env
source myproject_env/bin/activate  # enter isolation

Benefits:

Only THIS project's packages exist here
Other projects are completely unaffected
pip freeze > requirements.txt: EXACT list for deploy
Collaborator: pip install -r requirements.txt = identical!
No admin/sudo needed (user-owned folder)
Clean slate: delete the env folder to start over
bash 
python --version    # 3.11.5
pip list            # only 3 packages: requests, certifi, urllib3

Why Python 3.11+ Specifically?

Python 2.7: End of Life January 2020. DO NOT USE.
Python 3.6: f-strings added. Still common but old.
Python 3.8: Walrus operator (:=). Many servers use this.
Python 3.10: Pattern matching (match/case). Significant update.
Python 3.11: 10-60% FASTER than 3.10. Better error messages.
Python 3.12: Even faster, more improvements.

Python 3.11 improved error messages (huge for beginners):

bash 
# OLD Python error:
AttributeError: 'NoneType' object has no attribute 'split'

# NEW 3.11 error:
AttributeError: 'NoneType' object has no attribute 'split'
Hint: Did you forget to return a value from your function?

Check your current Python version:

bash 
python --version       # may show Python 2.7 on old Macs
python3 --version      # usually shows Python 3.x
py --version            # Windows alternative

IMPORTANT: On macOS/Linux, use python3 and pip3. On Windows (with Python 3 installed), use python and pip.
